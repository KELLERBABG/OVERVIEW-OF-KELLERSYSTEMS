1. Define a `MatchingEngine` struct in `engine.rs`:
```rust
pub struct MatchingEngine {
    bids: BTreeMap<Price, VecDeque<OrderId>>,  // price ascending (best bid first)
    asks: BTreeMap<Price, VecDeque<OrderId>>,   // price descending (best ask first)
    orders: HashMap<OrderId, Order>,
```

Where `Price` is a `u64` representing integer micro-units (1/1_000_000 of the base unit) to avoid floating-point issues. If `order.rs` already defines a price type, use it.

2. Implement `MatchingEngine::new() -> Self`.

3. Implement `pub fn submit(&mut self, order: Order) -> Vec<Fill>`:
   - Insert the order into `self.orders`.
   - If the order is a bid (buy): walk `self.asks` from lowest price upward. For each ask at price `p` where `p <= order.price`, match as much quantity as possible (partial fills allowed). Remove fully-filled asks from the book; decrement partially-filled asks. Collect all `Fill` records.
   - If the order is an ask (sell): symmetric logic walking `self.bids` from highest price downward.
   - After matching, if any quantity remains unfilled, insert the remainder into the appropriate price level in the BTreeMap (append to the VecDeque for time priority).
   - Return all fills generated by this submission.

4. Implement `pub fn cancel(&mut self, order_id: OrderId) -> Option<Order>`:
   - Remove from `self.orders` and from the relevant price-level VecDeque.
   - Return the cancelled order if it existed.

5. Implement `pub fn best_bid(&self) -> Option<(Price, u64)>` and `pub fn best_ask(&self) -> Option<(Price, u64)>` returning the top-of-book price and total resting quantity at that level.

6. Define a `Fill` struct (if not already in `order.rs`):

```rust
    pub price: Price,
    pub quantity: u64,
}
```

2. In `crates/sca-api/src/routes.rs`, add an Axum middleware layer for authentication:

```rust
use axum::extract::State;
use axum::http::{Request, StatusCode};
use axum::middleware::Next;
use axum::response::Response;
use sca_security::capabilities::/* whatever the capability type is */;

/// Extracts and validates an `Authorization: Bearer <token>` header.
/// For this phase, tokens are mapped to capabilities via a static lookup table
/// (no JWT — that's a later task). The table lives in `AppState`.
async fn auth_middleware(
    State(state): State<AppState>,
    req: Request,
    next: Next,
) -> Result<Response, StatusCode> {
    let token = req.headers()
        .get("authorization")
        .and_then(|v| v.to_str().ok())
        .and_then(|v| v.strip_prefix("Bearer "))
        .map(|t| t.to_string());

    match token {
        Some(t) => {
            let caps = state.token_capabilities.get(&t)
                .ok_or(StatusCode::UNAUTHORIZED)?;
            // Check that the request method maps to a required capability:
            //   GET  → read
            //   POST/PATCH/DELETE → write (or admin for DELETE)
            // If insufficient, return 403.
            let required = match req.method().to_string().as_str() {
                "GET" => Capability::Read,
                _ => Capability::Write,
            };
            if !caps.contains(required) {
                return Err(StatusCode::FORBIDDEN);
            }
            Ok(next.run(req).await)
        }
        None => Err(StatusCode::UNAUTHORIZED),
    }
}
```
