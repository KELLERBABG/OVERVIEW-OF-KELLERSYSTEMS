AMBIENT THERMAL ARBITRAGE (ATA) - PRODUCT & TECHNICAL OPERATOR FIELD GUIDE

================================================================================
1. EXECUTIVE ELEVATOR PITCH & REAL-WORLD REALITY
================================================================================

What is this system?
Ambient Thermal Arbitrage (ATA) is an industrial edge software gateway and automated control engine that connects to an existing cold storage refrigeration facility (industrial freezer warehouses, distribution centers, supermarkets) and turns the building's thermal mass into a giant thermal battery.

What problem does it solve for the customer?
Cold storage facilities run compressors constantly to keep goods frozen. Electricity prices fluctuate hourly on day-ahead and intraday power spot markets (ENTSO-E, EPEX SPOT), occasionally becoming extremely high, cheap, or even negative. Facilities also operate in power grids that pay industries to rapidly increase or decrease power demand for grid frequency stabilization (FCR / Primary Frequency Response). 

What does ATA do for them?
1. It pre-cools the facility when power prices are rock-bottom or negative, storing cooling energy inside the frozen goods and building envelope.
2. It shuts down or throttles down compressors when electricity is expensive, coasting on the stored cold.
3. It participates in lucrative grid frequency balancing by detecting subtle grid deviations (50 Hz / 60 Hz) and altering compressor power instantly.
4. It does all of this while mathematically guaranteeing that the food, pharma, or cargo temperature never crosses health and regulatory safety thresholds.

================================================================================
2. HOW IT INTEGRATES WITH PHYSICAL HARDWARE
================================================================================

Where does ATA sit physically?
ATA runs on a small industrial DIN-rail edge computer (such as a Siemens IOT2050, Advantech, or Raspberry Pi CM4 with RS-485 / Ethernet ports) mounted directly inside the facility's electrical control cabinet.

How does it connect to the existing chiller and PLC?
Code reference: crates/gateway/src/modbus_client.rs
Configuration: crates/gateway/config.toml

ATA does NOT rip out or replace the customer's existing PLC (Programmable Logic Controller like Carel, Danfoss, Dixell, Siemens S7). Instead, it talks to the existing PLC over standard industrial Modbus protocols:
- Modbus TCP via Ethernet cable (RJ-45)
- Modbus RTU via shielded twisted pair serial wire (RS-485 / COM port)

What registers does ATA touch on their PLC?
1. Input: Internal envelope temperature (signed int16, Celsius x 100)
2. Input: Ambient outdoor temperature (signed int16, Celsius x 100)
3. Input: Grid frequency (optional from local power meter, Hz x 100)
4. Output: Compressor Command Coil (0x05) or VFD Inverter Speed Register (0x06, 0..1000 = 0.0%..100.0%)
5. Output: Safety Alarm Output (0x05)

What about hardware watchdogs and crash prevention?
Code reference: crates/gateway/src/watchdog.rs
Industrial environments cannot afford silent software hangs. ATA natively monitors /dev/watchdog on the Linux kernel and systemd supervisor pinging every 5 seconds. If the edge box crashes, the hardware watchdog triggers. Upon planned operator shutdown, ATA sends the magic 'V' disarm byte to prevent false emergency reboots.

================================================================================
3. CONCRETE CAPABILITIES: WHAT IT DOES, WHAT IT WON'T DO, AND WHAT IT REQUIRES
================================================================================

WHAT IT DEFINITELY DOES:
- Continuously calculates TTF (Time-to-Feast / Time-to-Failure): exactly how many seconds the room can stay unpowered before reaching the safety temperature limit. (Code: crates/gateway/src/thermal/mod.rs)
- Employs an Anti-Short-Cycle Timer (ASCT) governor: enforces minimum run time (e.g., 900 seconds) and minimum off time (e.g., 600 seconds) to prevent mechanical wear and contactor burnout on compressors. (Code: crates/gateway/src/control/mod.rs)
- Uses Model Predictive Control (MPC) lookahead: looks 24 to 48 hours into the future day-ahead spot prices to find the absolute cheapest hours to pre-cool before expensive price spikes occur. (Code: crates/gateway/src/control/mod.rs)
- Supports continuous VFD modulation: if the chiller has a variable frequency drive, ATA uses a closed-loop PI controller to modulate speed (e.g., 40% to 100%) rather than brutal binary cycling, saving energy through improved COP. (Code: crates/gateway/src/control/mod.rs)
- Executes periodic oil-return flush pulses: when running compressors at low speeds for hours, refrigerant oil can pool in evaporator coils; ATA automatically commands periodic high-speed pulses to flush lubricating oil back to the compressor crankcase safely. (Code: crates/gateway/src/control/mod.rs)
- Distinguishes Air vs. Cargo Core temperature: uses a 2-node thermal lag model. Cold storage operators know air warms up in minutes during a door opening, but frozen pallet cores take 10 to 20 hours to warm up. ATA respects air limits but tracks true core thermal inertia so facilities can shed power during expensive hours without risking frozen inventory. (Code: crates/gateway/src/control/mod.rs)
- Serves an embedded local web dashboard: operators can view live status, temperature graphs, compressor modulation, and market spot prices by simply pointing a browser at http://gateway-ip:8085. (Code: crates/gateway/src/api/mod.rs)

WHAT IT WILL NEVER DO (HARD SAFETY GUARANTEES):
- It will NEVER allow temperatures to exceed the configured maximum threshold (e.g., -18.0 C). The moment TTF drops below the critical safety margin (e.g., 900 seconds) or temperature reaches limit, Emergency Mode overrides all financial optimization and forces 100% cooling power immediately.
- It will NEVER bypass the compressor anti-short-cycle locks for price arbitrage. Compressor mechanical integrity always overrides market opportunities.
- It will NEVER drop into an unrecoverable state if the internet goes down. If market price feeds (ENTSO-E) fail or internet disconnects, ATA enters Thermostat / Standalone fail-safe mode and maintains the standard setpoint like a conventional industrial thermostat.
- It will NEVER apply configuration changes that violate safety physics. If an operator attempts via the API (PUT /config) to set invalid parameters (such as minimum temperature higher than maximum, negative gains, or NaN values), the gateway rejects the request with HTTP 422 Unprocessable Entity.

WHAT IT REQUIRES FROM THE CLIENT SITE:
- A programmable or addressable refrigeration controller / PLC with exposed Modbus TCP or RTU registers.
- Temperature sensors mounted in the cold envelope.
- An outbound internet connection for spot electricity prices (or local manual price ingestion via REST API).
- 24V DC or 230V AC DIN rail power supply for the edge gateway box.

4. MODES OF OPERATION EXPLAINED CONCRETELY
================================================================================

Code reference: crates/gateway/src/control/mod.rs (ControlMode enum)

1. Emergency Mode:
Trigger: Internal temperature exceeds t_max or Time-to-Failure is below ttf_critical_sec.
Behavior: Maximum cooling (100% compressor speed or coil ON). Latches until room temperature recovers safely below recovery threshold.

2. ThermalGuard Mode:
Trigger: Accumulated thermal debt integral exceeds limit (e.g., 3600 K*s).
Behavior: Restores baseline temperature. Prevents the room from floating near the warm limit for too many hours consecutively.

3. GridBalancing Mode (Multi-Market Co-Optimization):
Trigger: Power grid frequency drifts outside the normal deadband (e.g., below 49.90 Hz or above 50.10 Hz in Europe).
Behavior: Continuous and economically co-optimized grid response:
- When VFD is enabled, compressor speed modulates continuously along a droop curve (+/-0.20 Hz -> +/-50% speed delta around the economic baseline) rather than brutal binary on/off switching.
- Economic profitability check: Over-frequency (power surge) allows cooling ramp-up provided the spot price isn't in extreme peak-shed territory OR frequency deviation is large (>+0.10 Hz) earning maximum FCR balancing revenue.
- If the room is already cold (-23 C) and resting in Arbitrage Shed, ATA captures grid surplus to pre-cool at effectively negative/discounted power while simultaneously stacking FCR balancing revenue.
- Hard safety bounds: Over-frequency will never over-chill below t_min; under-frequency (shedding) will never compromise cold chain above t_max - 1 C.

4. ArbitragePreCool Mode:
Trigger: Current electricity spot price is below the cheap threshold (or below the dynamic 25th percentile of the day).
Behavior: Runs compressor at full capacity down to t_min (e.g., -24.0 C), loading cold energy into the thermal mass while energy is cheap.

5. ArbitrageShed Mode:
Trigger: Current electricity spot price is above the expensive threshold (or above the 75th percentile of the day).
Behavior: Turns off compressor or drops VFD to minimum idle speed, allowing room air to drift upward safely while the cargo core remains frozen, avoiding peak tariff prices.

6. Thermostat Mode:
Trigger: Electricity price is normal / neutral.
Behavior: Standard hysteresis cycling around normal setpoint (e.g., -20.0 C), or modulated PI VFD speed matching the building's heat leak.

7. FailSafe Mode:
Trigger: Temperature sensor reads NaN, disconnected wire, or sensor failure.
Behavior: Runs compressor at a safe default duty cycle (e.g., 50% or continuous cooling depending on site safety rating) and raises the Modbus alarm coil to alert facility maintenance.

5. FINANCIALS AND BENCHMARKING (FLEET ENGINE)

Code reference: crates/fleet/src/main.rs
Simulation results: benchmarks/

How do we prove savings to a prospective customer before touching their hardware?
The repository contains the standalone Fleet Simulation Engine (`crates/fleet`), which simulates 365 days (8,760 hours) of physical thermal dynamics, actual historical ENTSO-E spot prices, ambient weather, and retail warehouse schedules.

Pre-configured cold storage archetypes in the engine:
- Large Distribution Center (50,000 m3, 1.5 MW cooling capacity)
- Medium Cold Storage (1,000 m3, 50 kW cooling capacity)
- Supermarket Central Freezer (500 m3, 25 kW cooling capacity)
- Small Walk-in Freezer (80 m3, 5 kW cooling capacity)

Demonstrated Results from the 1-Year Benchmark Data (see benchmarks/):
- Average electricity cost reduction: 12% to 22% solely from energy arbitrage.
- Additional revenue: FCR / frequency response grid balancing payments.
- Zero cold chain temperature violations across all 8,760 simulated hours.

6. OPERATIONAL AND COMMAND LINE CHEAT SHEET
================================================================================

To run the local edge gateway in simulation mode:
Command: cargo run -p thermal-arbitrage-mvp
Result: Starts edge runtime on http://127.0.0.1:8085.
Dashboard URL: Open browser to http://127.0.0.1:8085 or http://127.0.0.1:8085/ui.

To test the REST API manually:
- Get live status: curl http://127.0.0.1:8085/status
- Post a simulated price: curl -X POST http://127.0.0.1:8085/price -H "Content-Type: application/json" -d '{"price_eur_per_mwh": 120.0}'
- Scrape Prometheus metrics: curl http://127.0.0.1:8085/metrics

To run a 1-year fleet benchmark for a client:
Command: cargo run -p thermal-fleet -- --volatile "Medium Cold Storage NRW:1"
Result: Computes full year financial comparison vs baseline thermostat, logs duty cycles, and writes detailed CSV to benchmarks/.

To verify entire system integrity:
Command: cargo test --workspace
Command: cargo clippy --workspace --all-targets -- -D warnings
Result: All 126 unit/integration tests pass, 0 warnings.
