OP-Roboter

01 — the gateThree ways a surgical robot hurts someone

A teleoperated instrument passes through a single small incision. That entry point is a remote centre of motion: the shaft may pivot there but must not translate sideways through the abdominal wall, or the port tears. The tip must stay out of named structures. And it must not move faster than the tissue can tolerate.

Those are three different constraints, and OP-Roboter checks all three in the same proof. The surgeon's commanded motion becomes a trajectory; the trajectory becomes a satisfiability query against the fixtures; and the joint command is released only if the query is unsatisfiable — meaning no reachable state violates any of them.

[CYCLE 001] [OP-GATE]        Real-time execution gate initialised. 7-DOF Jacobian loaded.
[CYCLE 001] [GATE-PASS]      Trajectory admitted. RCM error < 0.2 mm. Command released to servos.
[CYCLE 002] [GATE-REJECT]    Trocar lateral shear predicted 2.1 mm > 1.5 mm limit. Clamped.
[CYCLE 003] [GATE-REJECT]    Tip path enters hepatic artery no-go volume. Halted.

02 — the cratesOne verification layer per crate

The control loop is zero-allocation, so nothing in the gate can pause for memory while a tool is inside a patient. Each crate owns one layer of the proof.

Crate 01op-kinematics

Analytical and numerical forward and inverse kinematics, Denavit-Hartenberg parameters, geometric Jacobian.

Crate 02op-constraints

Compiles physical actuator velocity limits, joint ranges and the trocar pivot into solver constraints.

Crate 03op-gate

Evaluates the trajectory query per control cycle and either releases or clamps the command.

Crate 04op-fixtures

Volumetric no-go regions registered against the patient model and checked as first-class geometry.
