Mathematical certainty inside the Rust compiler

Keller-Verify is an offline formal verification engine embedded in rustc. It intercepts optimized Mid-level Intermediate Representation (MIR) to mathematically prove the absence of panics, integer overflows, division-by-zero, and memory slice bounds violations via Z3 SMT-LIB solving.

Verification Output

Keller operates as a drop-in RUSTC_WRAPPER during cargo check. When an invariant holds over all reaching inputs, it is mathematically proven (PASS). When a violation is possible, the exact witness valuation is recorded: 

$ keller verify --crate wan_mesh
[PASS] Verified formal integrity: sum_guarded (bb1)
[PASS] Verified formal integrity: slice_guarded (bb1)
[PASS] Pointer provenance valid: NonNull non-null & aligned (bb6)
[FAIL] Arithmetic Overflow Detection (AddWithOverflow)
       -> Counterexample: [x (_1) = 192, 100_u8 = 100] in sum_under_guarded (bb1)
[FAIL] Slice Index Out of Bounds
       -> Counterexample: shards.len() = 1 at index = 2 in dec_join_tamper_resistant (bb7)

Total assertions checked: 498 | PASS: 394 | FAIL: 104 | WARN: 0
Generated obligations: obligations/wan_mesh/*.smt2

Verification Pipeline

The system operates deterministically in five distinct stages without inserting runtime instrumentation into target binaries:

  1. Stage 01 RUSTC_WRAPPER Hook Captures the compiler build invocation transparently. No modifications to Cargo.toml or source files are required.
  2. Stage 02 MIR CFG Inspection During rustc's after_analysis callback, the verifier traverses the Control Flow Graph (CFG), basic blocks, and terminators of each local function.
  3. Stage 03 Formula Construction Branch conditions and assertion guards are translated into path-sensitive SMT-LIB constraints using unbounded integer arithmetic and bit-width boundaries.
  4. Stage 04 SMT Solving (Z3) Queries the Z3 solver: unsat constitutes a formal proof of safety; sat extracts a counterexample model. Undecided queries yield a disclosed WARN.
  5. Stage 05 Artifact & Test Synthesis Writes deterministic SMT-LIB 2.6 obligations (.smt2) and generates native, reproducible #[should_panic] regression tests via keller testgen.

Formal Assertion Semantics

Rust inserts explicit runtime checks to enforce language invariants. Keller proves them at compile time:

Assertion Kind Formal Encoding Guarantee Proved
Slice Bounds Type-aware bounds over index expressions v[i] against inferred capacity. Proves i < len across all reachable execution branches.
Arithmetic Overflow Integer arithmetic (Add, Sub, Mul, Neg) bounded by exact bit-widths (u8 through u128). Guarantees operations cannot exceed type boundaries or panic under debug checks.
Division & Remainder Symbolic denominator checking including signed MIN / -1 overflow. Proves the divisor is strictly non-zero.
Bitwise Shifts Validates shift operands against the target integer width. Guarantees shift count is strictly less than T::BITS.
Option / Result Unwrap Decides enum variant discriminants when statically reachable in the compiler CFG. Flags ground None/Err as bugs; proves Some/Ok safe.
Pointer Provenance Non-null and memory alignment constraints constructed from std::ptr::NonNull. Proves raw pointer operations maintain valid alignment invariants.
Async Drop Invariant Coroutine state machine invariant checking (ResumedAfterDrop). Proves futures and async tasks are not polled after completion or cancellation.

Auditable Proof Obligations

Every decision emitted by Keller is accompanied by an independent SMT-LIB 2.6 obligation file. Verdicts do not require trusting Keller: any third party can independently re-discharge the obligation directly using z3 -smt2 <file>.

Below is a verbatim obligation generated from an overflow finding in a branch-merge test case: 

; keller-verify proof obligation (SMT-LIB 2.6)
; crate:    branch_merge
; function: bump
; block:    bb3
; kind:     overflow
; verdict:  FAIL (sat)
; witness:  overflow_l = 255 (_3), overflow_r = 100, flag (_1) = true
(declare-fun phi_bb3_2 () Int)
(declare-fun overflow_l () Int)
(declare-fun overflow_r () Int)
(declare-fun mir_1 () Int)
(assert (= overflow_l phi_bb3_2))
(assert (= overflow_r 100))
(assert (or (> (+ overflow_l overflow_r) 255) (< (+ overflow_l overflow_r) 0)))
(assert (or (= mir_1 0) (not (= mir_1 0))))
(assert (or (and (= mir_1 0) (= phi_bb3_2 0)) (and (not (= mir_1 0)) (= phi_bb3_2 255))))
(assert (>= mir_1 0))
(assert (<= mir_1 1))
(check-sat)
sat

When Z3 returns sat, the solver model is written to a companion .witness.smt2 file. Executing keller testgen automatically turns this counterexample into a native Rust unit test: 

$ keller testgen obligations/branch_merge/bump_bb3.witness.smt2
Synthesized unit test for 'bump' (bb3) -> src/tests/generated_keller_tests.rs

#[test]
#[should_panic(expected = "attempt to add with overflow")]
fn test_keller_witness_bump_bb3() {
    let flag = true;
    let _ = bump(flag);
}

Soundness Boundaries & Limits

Rigorous verification requires explicit disclosure of analytical boundaries. Keller operates under the following design constraints:

  • Debug Profile Semantics: Analyzes debug semantics where rustc emits assertion checks. In release builds without overflow-checks = true, integer operations wrap rather than abort.
  • Intra-Procedural Scope: Reasoning operates on individual functions. External crates and dynamic dispatch boundaries are treated as unconstrained symbolic return values unless pinned.
  • Bounded Loop Unrolling: Loops are unrolled up to a bounded trip threshold. Inductive loop-carried variables beyond the threshold are widened to their full type domains.
  • Opaque Bit-Casts: Non-linear bitwise twiddling and narrowing pointer-casts yield unconstrained type-bounded symbols.

Installation & Integration

Keller is distributed as standard Rust tooling and requires a pinned nightly compiler (with rustc-dev) and Z3 4.16.0 installed. 

# 1. Clone and compile the toolchain
git clone https://github.com/KELLERBABG/Formal-Verification.git
cd Formal-Verification
cargo build --release

# 2. Verify a target crate
cd /path/to/your/crate
keller verify

# 3. Continuous Integration: Gate Pull Requests with SARIF
keller verify --baseline .keller-baseline.json --sarif keller.sarif
